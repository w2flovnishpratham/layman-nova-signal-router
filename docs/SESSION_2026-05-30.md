## 2. Comprehensive Audit — Unhandled / Partial Scenarios

Categorized by severity. Each item: **what can happen** → **what NOVA currently does** → **what it should do**.

### 🔴 CRITICAL (fix before next real-money session)

| # | Scenario | Current behavior | Fix needed |
|---|---|---|---|
| C1 | Position still open at 15:20 IST | Dhan auto-squares with penalty + slippage | Add 15:15 IST scheduled flatten task |
| C2 | Manual entry on Dhan (outside NOVA) | Invisible to dashboard; only blocks NOVA's next signal | Background reconciler polls Dhan every 30s and surfaces external positions |
| C3 | Manual exit of NOVA position | Dashboard shows stale "open" until next reconciler trigger; exit P&L not in NOVA log | Same background reconciler clears + logs |
| C4 | Manual SL/TP modification on NOVA position | Undetected; dashboard shows NOVA's stale levels | Compare Dhan's actual SL order trigger vs NOVA's recorded value, flag drift |
| C5 | Dhan API timeout mid-order | Webhook 500; order may or may not have been accepted by Dhan | Idempotent retry using `correlationId`; on retry, query Dhan for orders matching correlationId before re-sending |
| C6 | Backend restart with open position | `start_option_position_monitor()` runs but doesn't re-verify against Dhan, doesn't re-arm Super Order legs | On startup: query Dhan, compare with local state, log any discrepancy, re-verify Super Order legs exist |
| C7 | Seen-signals file grows forever | New signal_ids appended to a list; no TTL | Add 24h TTL, prune on access |
| C8 | Multi-process state writes | `threading.RLock()` is per-process; `uvicorn --workers 2+` would corrupt JSON state | Either enforce single-worker, or move to SQLite/Postgres with row locks |
| C9 | Two concurrent webhook signals (different signal_ids, opposite sides) | Both pass `_PROCESSING_LOCK`, both read empty position, both proceed → long CE + long PE simultaneously | Per-strategy-code mutex at webhook level, not just per-signal-id |
| C10 | Partial order fill | NOVA records `qty=65, filled_avg_price=120`; reality might be `filled=30, rest expired`. SL/TP set as if 65 | Inspect `filled_qty` in poll response; if < requested, log warning and adjust |
| C11 | **Settings race during signal processing** | Signal in flight reads runtime settings; user clicks Save mid-trade; same minute's two trades get different SL% | Capture runtime settings into signal context at start of `route_signal`, use captured copy throughout |

### 🟡 HIGH (fix this week)

| # | Scenario | Current behavior | Fix needed |
|---|---|---|---|
| H1 | Token expires mid-session (Dhan tokens last ~24h) | Order placement fails with 401; logged; signal lost | Proactive: before each signal, check `token_expired` from `dhan_token_age_metadata()`. Refresh or block with clear UI banner |
| H2 | Webhook secret leaked | Anyone hitting the URL with the secret can place orders | Add HMAC signature verification, timestamp freshness window (60s), nonce |
| H3 | No rate limit on `/setup/dhan/*` | Attacker can brute-force token + client_id combinations | Per-IP rate limit (5 attempts / 5 minutes) |
| H4 | `connect_dhan` partial-state failure | validate succeeds → save fails → user sees error but state is half-saved | Wrap 3-step sequence in try/except with explicit rollback |
| H5 | Risk settings business rules | Pydantic catches types but not ranges; user can set SL=−50% or 99999% | Validators on `RiskSetupRequest`: 0 < sl_percent < 80, 0 < tp_percent < 500, max_qty ≥ NIFTY lot size |
| H6 | Double-click on form submit | Two API calls, two audit log entries | Frontend: disable buttons while request in flight |
| H7 | Destructive control endpoints have no confirmation | `/control/fresh-start`, `/control/panic-exit`, `/control/global-kill-switch` accept a simple `{enabled: bool}` | UI confirmation modal (already have `ConfirmModal.tsx` — verify wired); for `/control/fresh-start` also require typed confirmation in body |
| H8 | Concurrent settings edits (multi-tab) | Last write wins; earlier edits silently lost | Add `version` field to settings; reject saves with stale version |
| H9 | Backend restart during form submission | Request times out; user re-submits; might overwrite intervening changes | Graceful shutdown that flushes state; startup logs "clean" vs "crash" |
| H10 | Webhook secret strength | Accepts any string including "1234" | Enforce minimum length 16 + entropy check |
| H11 | No CSRF protection on POSTs | Currently mitigated because no cookie auth; risk lands when auth is added | Add CSRF tokens when introducing user login |
| H12 | Scrip master refresh blocks UI for 30+s | Synchronous; UI shows spinner with no progress; refresh kills request from UI's view (continues server-side) | Kick off async task, return job ID, poll `/setup/scrip-master/status` |
| H13 | OCO race between SL and TP | Same-tick fills of both → double exit, position goes from +qty to −qty | Use Dhan postback URL to subscribe to order updates; on `TRADED` for one leg, immediately cancel the other |
| H14 | WebSocket LTP feed reconnect | Behavior on Dhan WS drop during open position not explicitly tested | Test with simulated disconnect; verify REST fallback kicks in within `ws_stale_seconds` |

### 🟢 MEDIUM (roadmap)

| # | Scenario | Current behavior | Fix needed |
|---|---|---|---|
| M1 | No log rotation | JSONL files grow unbounded | Size-based rotation, drop oldest |
| M2 | No margin / funds pre-check | Order sent → Dhan rejects for insufficient funds | Local check using wallet snapshot |
| M3 | No critical-event notifier | Errors only in logs; nothing pushes to phone | Slack webhook for kill switch trips, daily loss limit, token expired, exit failures |
| M4 | Audit log write failures silent | Disk full / permission denied → order placed but no log entry | Surface log-write failures to dashboard |
| M5 | Dhan rate limits not respected | Tight modify/poll loops could hit Dhan rate limit | Token-bucket on Dhan client calls |
| M6 | Pydantic error responses leak schema structure | Default validation responses expose field names | Custom error handler sanitizes |
| M7 | Frontend doesn't preserve form state on backend error | User re-types lost data | Preserve all form fields on 4xx/5xx |
| M8 | Failed auth attempts lack IP/UA in audit | Can't trace attackers | Include `request.client.host`, UA in audit metadata |
| M9 | `/debug/*` endpoints in production | Exposes internals if accessible | Gate behind `APP_ENV != production` or admin auth |

==================================================
STRATEGY MODE (source declares strategy(...))
==================================================
Do not replace strategy orders with novaBuyCeSignal / novaBuyPeSignal /
novaExitSignal booleans. Preserve every original order call unchanged and
attach an alert_message argument that calls the frozen novaWebhookPayload
helper (appended server-side; call it, never redefine or reproduce it):

- strategy.entry / strategy.order with strategy.long:
  alert_message=novaWebhookPayload("BUY_CE", "<order id or event key>")
- strategy.entry / strategy.order with strategy.short:
  alert_message=novaWebhookPayload("BUY_PE", "<order id or event key>")
- strategy.close / a strategy.exit that fully closes the position:
  alert_message=novaWebhookPayload("EXIT", "<order id or event key>")
- strategy.close_all:
  alert_message=novaWebhookPayload("EXIT", "CLOSE_ALL")

Do not attach alert_message to strategy.cancel or strategy.cancel_all --
cancellation changes pending-order state but is not a fill and must not
generate a NOVA action. Do not add a bare alert() or alertcondition() call
anywhere; order-fill reporting happens only through alert_message on the
order calls themselves. Do not emit an alert directly from a raw entry
condition when the source uses a pending stop or limit order -- the report
must correspond to the actual order fill, which TradingView triggers.

alert_message is required instrumentation on every order-producing call
regardless of whether the source had any alert()/alertcondition()/webhook
mechanism of its own. A source with plain strategy.entry calls and no
existing alerting at all still needs alert_message added -- "preserve
everything unchanged" governs the strategy's calculations and order logic,
not whether you add the one piece of instrumentation this conversion exists
to add. Never return a candidate with an order-producing call missing it.

Do not rewrite or remove TradingView reversal logic. An opposite
strategy.entry stays an opposite strategy.entry; its NOVA action is BUY_CE or
BUY_PE exactly as above. NOVA's backend already closes the existing position
and opens the opposite one when it receives an opposite-side action while a
position is open -- do not invent a second signal or a synthetic EXIT for a
reversal entry. When a source has unambiguous long and short entries but no
explicit exit-only condition, interpret the opposite entry as a reversal:
generate only the new BUY_CE or BUY_PE alert_message and rely on NOVA's
server-side EXIT_THEN_ENTER; do not generate a separate synthetic EXIT.

strategy_layer for this mode is the complete preserved strategy body
(everything above, with alert_message additions only). Do not include the
transport helper block itself in strategy_layer; NOVA appends the exact
frozen block server-side. STRATEGY MODE sources already declare strategy(...)
with real order calls and are backtestable in TradingView as-is -- set
backtest_layer to null for STRATEGY MODE.

INDICATOR MODE (source declares indicator(...))
==================================================
Preserve all calculations, inputs, plots, and alertcondition logic. Map only

  bool novaBuyCeSignal

CLASSIFICATION
Return exactly one status:
